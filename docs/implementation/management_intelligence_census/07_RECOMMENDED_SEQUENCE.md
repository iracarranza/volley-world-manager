# Recommended Sequence After M9

This is a dependency sequence, not permission to interrupt the current M9 task.

## Phase 1 — Re-census against M9

Re-run this packet's claims after M9 lands. In particular, trace tactic consumers, setter option decomposition, block/floor choices and opponent symmetry.

## Phase 2 — Learned preference substrate

Implement the state that match training actually needs:

- hitter coordinate comfort;
- tempo comfort with relationship ownership;
- defensive loci/courses at rotation-slot grain;
- block posture at blocking-pair grain.

Layer these over natural rating-derived capability.

## Phase 3 — Planner becomes diagnostic

Decompose presets into concrete asks. Score each ask against current comfort. Make the planner identify the worst gap rather than requiring the manager to audit everything manually.

## Phase 4 — Match training as a live appointment

Allow assistant auto-resolution and attended live sessions to write the same learned-preference state. Preserve time as the resource.

## Phase 5 — Play Designer

Build the direct-manipulation demonstration interface only now. It authors asks; it does not create another tactics/training model.

## Phase 6 — Match-earned drift

Connect successful emergent match behavior to the same learned-preference channels where semantically appropriate. Allow manager to encourage or revert the drift in later training.

## Phase 7 — Adaptation proof

Certify repeated offensive concentration -> exposure -> defensive read/position -> setter response, including opponent symmetry and non-vacuous populations.

## Phase 8 — Scouting epistemics

Freshness, regional knowledge, scout claim history, demonstration-gated rare discoveries. Keep recruitment scouting separate from in-match opponent reading.

## Phase 9 — Derived style/knowledge UI

Expose evidence-based descriptors and training/adaptation information only after the underlying quantities are live.

## Why this order

The project already has more interface/design ideas than authoritative learned state. Building UI first would force presentation objects to invent their own meaning. The sequence above establishes ownership before representation.
